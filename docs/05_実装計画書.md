## 1. 目的と範囲

設計書 8節のマイルストーン(M1〜M7)を、作業単位・テスト・完了条件まで具体化する。
あわせて、実装に入る前に解消しておくべき文書間の不整合・未定義事項(3節)を挙げる。

- 本書は「何をどの順で作り、何をもって完了とするか」を扱う。仕様・設計そのものは 02・03 を正とする。
- 作業項目の ID は `M<番号>-<連番>` とする。ID は再利用せず、既存の番号を変えない。

## 2. 進め方の原則

### 2.1 基本方針

- マイルストーンは M0 → M7 の順に進める。前のマイルストーンの完了条件を満たしてから次へ進む。
- 下位モジュールから作る(errors/model/fsutil → codecs/chunkers → store → history/worktree → repo → cli)。上位→下位の一方向依存(設計書 1.1節)を崩さない。
- 各作業項目は「実装 + 単体テスト」を1組とし、テストの無い実装を残さない。
- 安全性に関わる処理(原子的書き込み、復元トランザクション、パス検査)は、正常系より先に障害注入テストを書く。
- 実装中に仕様・設計の変更が必要になったら、先に該当文書を更新し(文書バージョンと日付も更新)、それから実装する。

### 2.2 作業項目の完了の定義

1. 実装とテストがあり、`python -m pytest` が全件成功する。
2. 単体テストは `python -m unittest` でも実行できる。
3. テスト名またはコメントで、04_テスト観点.md の観点 ID を参照している(該当するもの)。
4. Python 3.11 の構文・標準ライブラリだけを使っている(3.12 以降の機能を使わない。3.3 節 I-12)。
5. 実行時の依存が標準ライブラリのみ(`dependencies = []` のまま)。

### 2.3 バージョン管理

- 履歴操作は jj で行う。作業項目のまとまりごとに `jj describe` / `jj new` で区切る。
- マイルストーン完了時に、説明に `M<番号> 完了` を含む変更を作る。

### 6.2 障害注入

- fsutil の `_fault_hook` に段階名(例: `atomic_write:HEAD.json`、`replace:swap:3`、`chunk_write`)が渡される。テストは、指定の段階名・回数で例外を送出する関数を差し込む。
- 例外の後は、同じプロセスで Repo を開き直して(recover を経由させて)状態を確認する。

### 6.3 強制終了

- `tests/integration/kill_driver.py` を subprocess で起動する。ドライバは `Repo` を開いて操作を行い、progress コールバックと `_fault_hook` で段階名を1行ずつ標準出力に書き、指定の段階で待機する。
- 親プロセス(テスト)は指定の段階名を読んだら子プロセスを kill し、その後 `Repo.open`(recover)→ `verify` → 作業ファイルのハッシュを確認する。
- 本体のコードにはテスト専用の分岐を入れない。

### 6.4 破損の再現

`tests/helpers.py` に、チャンクの削除・1バイト反転・切り詰め・codec ID の書き換え、JSON の破壊、パスの書き換え(再ハッシュして名前を合わせる改ざんを含む)を行う関数をまとめる。

### 6.5 実行

時間のかかるテスト(`slow`)は、既定では skip し、明示したときだけ実行する(I-15)。

- pytest: `tests/conftest.py` に `--run-slow` オプションを追加し、`pytest_collection_modifyitems` で `slow` の項目に skip を付ける。ただし、テストをノード ID(`ファイル::クラス::関数`)で個別に指定した場合は skip しない。GUI(VS Code のテストエクスプローラ等)で1件を選んで実行すると、ノード ID 指定になるので実行される。
- `-m "not slow"` を addopts に入れる方式は採らない(GUI で個別に選んでも選択から外れてしまうため)。
- unittest 形式の単体テスト: `tests/helpers.py` の `slow` デコレータ(`unittest.skipUnless(os.environ.get("BVC_RUN_SLOW"), ...)`)を使う。pytest の `--run-slow` はこの環境変数も設定する。単体テストで pytest を import しなくて済むようにするためである。
- 長いパスの道筋(I-16): 環境変数 `BVC_TEST_LONG_PATH` があれば、`tests/helpers.py` が import 時に `fsutil.LONG_PATH_THRESHOLD` を 0 に差し替える。pytest の `--force-long-path` はこの環境変数を設定する(強制終了テストの子プロセスにも引き継がれる)。本体は環境変数を読まない。Windows では既定の実行に加えて、この設定でも全テストを流す。
- LongPathsEnabled が無効な環境の模擬(M4-12): `tests/helpers.py` の `no_long_paths()` の中では、監査フックが `\\?\` の無い長いパス(260 文字以上、フォルダ作成は 248 文字以上)を OS に渡す操作を `FileNotFoundError` にする。`os.stat` など監査イベントの無い操作は対象外。


```
python -m pytest                 既定(slow は skip)
python -m pytest --run-slow      slow も含めて全部
python -m pytest --run-slow -m slow   slow だけ
python -m pytest --force-long-path   すべてのパスを \\?\ 付きにして実行(Windows)
python -m pytest -m "not git"    git の無い環境
python -m unittest discover -s tests -t .   単体テストのみ(unittest)
```
