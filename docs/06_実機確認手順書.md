# bvc 実機確認手順書

- 文書バージョン: 0.1(2026-09-26)
- 関連文書: 02_仕様書.md、03_設計書.md、05_実装計画書.md(M5-5)、build_pyz.md

---

## 1. 目的

自動テストでは確かめにくい項目(配布形態での起動、端末での表示、OS の設定・ネットワーク環境への依存)を、Windows の実機で確認する手順と結果をまとめる。
自動テスト(`python -m pytest`)が通っていることを前提とする。

- 項目の ID は `W-<番号>` とする。ID は再利用せず、既存の番号を変えない。
- 結果は 4節の表に、実施日・環境・結果を追記する。

## 2. 準備

1. 配布物を作る: `python scripts/build_pyz.py`(`dist/bvc.pyz` と `dist/bvc.cmd` ができる)。
2. 確認用の空のフォルダを作り、PowerShell で開く。以下、`bvc` は `dist\bvc.cmd` のフルパス(または PATH に加えたもの)を指す。
3. 確認用のファイルを作る(例: `fsutil file createnew big.bin 1073741824` で 1GiB の空ファイル。中身のあるファイルなら、手元の大きなバイナリを複製する)。

## 3. 確認項目

| ID | 項目 | 手順 | 期待する結果 |
|---|---|---|---|
| W-1 | ビルド | 2節の 1 | `dist/bvc.pyz` と `dist/bvc.cmd` ができる。`python dist\bvc.pyz --version` が pyproject.toml の version を表示する |
| W-2 | 基本シナリオ | `bvc init --track "*.bin"` → ファイルを変更 → `bvc commit -m 変更` → `bvc undo` → `bvc redo` → `bvc log` → `bvc branch` → `bvc verify` | 各コマンドが終了コード0で終わり、undo/redo でファイルの内容が戻る・進む。log がツリーで表示される |
| W-3 | 終了コード | PowerShell で `bvc goto 99; $LASTEXITCODE`(1)、根で `bvc undo; $LASTEXITCODE`(4)、`bvc goto; $LASTEXITCODE`(2)。cmd.exe でも `bvc undo` の後に `echo %ERRORLEVEL%` | 括弧内の終了コードになる(仕様書 2.2節) |
| W-4 | --json | `bvc --json log \| ConvertFrom-Json`、`bvc --json goto 99 \| ConvertFrom-Json`。日本語のファイル名・メッセージを含める | PowerShell で解析でき、日本語が化けない。エラーでも `exit_code` を含む JSON になる |
| W-5 | リダイレクト・パイプ | `bvc log > log.txt`、`bvc log \| more`、Git Bash で `bvc log \| cat`(分岐を含む履歴で) | 文字化け・`UnicodeEncodeError` にならない。出力先が cp932 なら `╯` が `┘` になる |
| W-6 | 進捗表示 | 1GiB 程度のファイルで `bvc commit`、`bvc undo`、`bvc verify` を Windows Terminal と従来のコンソール(conhost)で実行する | 1行が上書きで更新され、終了時に消える。お知らせの行と混ざらない。`bvc commit 2> err.txt` では err.txt に進捗が書かれない |
| W-7 | Ctrl+C | 大きなファイルの commit・undo の途中で Ctrl+C を押し、その後 `bvc log`、`bvc verify` | 終了コード3で止まる。次のコマンドで復旧(recover)して、verify で異常が無い。作業ファイルは元の内容か移動先の内容のどちらか(混ざらない) |
| W-8 | 使用中のファイル | 追跡ファイルを別のアプリ(Excel、画像エディタなど)で開いたまま `bvc undo` | 終了コード3で中止し、作業ファイルは変わらない(R-4) |
| W-9 | Python 3.10 | `uv run --isolated --no-project --python 3.10 --with "pytest>=8" --with-editable . python -m pytest`(I-12) | 全テストが通る |
| W-10 | 長いパスの道筋 | `python -m pytest --force-long-path` | 全テストが通る |
| W-11 | LongPathsEnabled 無効 | 管理者で `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled` を 0 にして再起動し、260 文字を超える深さのフォルダで W-2 と、`python -m pytest tests/integration/test_path_safety.py` を実行する(終わったら元に戻す) | 基本シナリオが動く。長いパスのテストが通る(P-6、M4-12 からの持ち越し) |
| W-12 | ファイルサーバー・NAS | 実際のファイルサーバー・NAS の共有フォルダ(UNC とドライブ割り当ての両方)で W-2 と `bvc gc`・`bvc discard` | 誤って中止することなく動く(I-16、M4-12 からの持ち越し) |
